**1. Ownership of words ≠ creation.** "I never reword your words" must be symmetric: once a person edits the title/description, those are their words. Add `text_last_edited_by` (person|key), flipped only on substantive edits to title/description/checklist text — never on position, labels, waiting_on (trivial edits must not transfer ownership). Agent may reword iff it holds text ownership; `created_by` stays for attribution and `delete_tasks: own`. Created-by alone means the agent can steamroll a human's rewording, which is exactly the failure the policy exists to prevent.

**2. Token-in-text is not a link; it's a link with a delete button.** Failure modes: any description rewrite silently unlinks (no error, no diff); the agent *summarizing* its own description kills links it meant to keep; duplicate appends under replay; stale frozen labels; dead tokens after an interaction is deleted; a person's reflow mangling `#[...]` syntax; no link metadata (who/why/when). Worst: GET returns the token inside the text, so the read shape itself invites the corruption. The API must own a join table (`task_interactions`: task, uuid, added_by, added_at) with POST/DELETE `/tasks/{id}/interactions`, description kept clean, `interactions: [...]` as a first-class field. Render mentions *from* the join for humans. Cheapest migration: one pass converting existing tokens, then ignore tokens on write.

**3. Briefing.** ~0.5–1 KB/task → **25–50 KB**. Fine once, expensive if polled per cycle; truncate latest notes to one line, target <30 KB. Order is wrong: `position: top` is newest-first — an ordering that actively fights "what's next." Correct order: **agent's own in_progress tasks first**, then priority, then oldest-created as tiebreak. Done-today: yes, include as a compact id+title tail — the agent needs them for the daily note and will otherwise make a second call. The missing field for context reset: **`my_last_note` — its own latest outcome + next_steps, at the top**. The design already made the daily note the handoff artifact; the briefing just has to hand it back.

**4. Ongoing.** `caught_up` needs `caught_up_at` (and what tripped it: all tasks done). "Caught up" without a date is unfalsifiable and unreportable — the boss's first question is "since when?" Parent's row should read `caught_up (2026-10-04)`, never `in_progress 100%` — the percentage asserts the completion semantics manual mode exists to deny. An ongoing project should not offer: End/Complete button (archive/pause is fine, complete is not), progress bar, percent, or ETA. Start is fine; anything that *predicts an ending* is the lie.

**5. Corrections.** Manager key amending human billable time: acceptable **only** with attribution to the key and its minter, and before/after in the feed (present). The unacceptable half is **DELETE removing any kind**: billable rows should never be erasable — deletion of billable becomes an amendment to zero with a note, so the ledger is append-with-corrections, not erasable. `amend_own_ledger: true` for agent keys is right, and tokens/cost estimates should absolutely be amendable — they're flagged `estimated`; a corrected estimate beats a duplicated row. Keep the before-value in the feed (already does).

**6. Same-second window.** Real but small at 1/min: a write landing in the same second as `now` (or truncating into it) is skipped forever. Cheapest fix: **`>=` plus client dedupe by uuid** — at ≤50 tasks the seen-set is trivial. Overlap-by-one-second with strict `>` also works but leaves the boundary inside the overlap; `>=` + dedupe is simpler to document. The right fix is a monotonic cursor (sequence/xmin token) — do it if cursors arrive anyway (Q7).

**7. Wouldn't ship:** DELETE /entries/{id} as an unconditional any-kind eraser (Q5) — an erasable billable ledger is the one unrecoverable mistake here. **Missing, hit first:** the briefing's hard 50 cap — the 51st open task is simply invisible, with no `total_open`/`truncated: true` and no cursor on `/tasks`. An agent will confidently work a subset and never know. Ship `total_open` + a cursor before anything else on this list.
